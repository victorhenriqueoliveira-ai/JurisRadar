# ADR-003: Stripe como Gateway de Billing e Assinaturas

## Status

Aceito

## Data

2026-08-19

## Contexto

O JurisRadar SaaS precisa de um sistema de billing para gerenciar assinaturas mensais (R$157/mês) e anuais (R$127/mês = R$1.524/ano), trial de 14 dias, upgrade/downgrade, cancelamento e portal self-service. O projeto não tem nenhum código de pagamento atualmente.

## Decisão

Usar Stripe como gateway principal. Configurar dois Stripe Products (mensal e anual) com Stripe Prices em BRL. Usar Stripe Checkout para o fluxo de assinatura e Stripe Customer Portal para o self-service. Webhooks do Stripe atualizam o status da assinatura no banco via endpoint `/api/billing/webhook`.

## Alternativas Consideradas

### Alternativa B: Pagar.me

- **Descrição**: Gateway brasileiro com Pix nativo, boleto e suporte em português.
- **Prós**: Pix nativo sem workarounds, suporte local, regulação brasileira.
- **Contras**: SDK TypeScript menos maduro que o Stripe; Customer Portal precisa ser construído do zero; documentação inferior; webhooks menos confiáveis segundo relatos da comunidade.
- **Por que rejeitada**: O overhead de construir o portal self-service e lidar com SDK inferior supera o benefício do Pix nativo (Stripe suporta Pix via Stripe Financial Connections no Brasil).

### Alternativa C: Stripe + Pagar.me (híbrido)

- **Descrição**: Stripe para cartão/assinatura, Pagar.me para Pix/boleto.
- **Prós**: Melhor cobertura de métodos de pagamento brasileiros.
- **Contras**: Dois sistemas de webhook, dois dashboards, lógica de reconciliação dupla. Complexidade injustificada para o MVP.
- **Por que rejeitada**: YAGNI — iniciar com Stripe e avaliar Pagar.me se a taxa de conversão via Pix for relevante.

## Consequências

### Positivas

- Stripe Customer Portal elimina ~2 semanas de desenvolvimento de portal self-service.
- SDK TypeScript oficial (`stripe` npm package) com tipos completos.
- Stripe Billing lida automaticamente com falhas de cobrança, dunning e retentativas.
- Dashboard Stripe centraliza métricas de MRR, churn e cohorts.

### Negativas

- Pix requer configuração adicional (Stripe Financial Connections); pode não estar disponível imediatamente no lançamento.
- Taxa do Stripe (~2,9% + R$0,30 por transação) ligeiramente superior ao Pagar.me para volumes baixos.

### Riscos

- **Indisponibilidade do Stripe**: Mitigação — webhook idempotente com retry; acesso da aplicação não é bloqueado sincronamente aguardando confirmação do Stripe.

## Notas de Implementação

- Tabela `subscriptions` com campos: `stripe_customer_id`, `stripe_subscription_id`, `status` (trialing/active/past_due/canceled), `current_period_end`, `plan` (monthly/annual).
- Middleware de acesso verifica `subscription.status in ('trialing', 'active')` antes de liberar rotas protegidas.
- Stripe webhook handler deve ser idempotente (verificar se evento já foi processado pelo `stripe_event_id`).
