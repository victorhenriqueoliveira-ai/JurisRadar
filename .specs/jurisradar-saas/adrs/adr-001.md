# ADR-001: Estratégia de Lançamento — Plataforma Completa vs MVP Faseado

## Status

Aceito

## Data

2026-08-19

## Contexto

O JurisRadar é uma ferramenta interna de busca de processos jurídicos (DataJud, DJe TJSP, PJe/Comunica) que será transformada num SaaS público para advogados e escritórios de advocacia. A decisão central de produto é: lançar com o conjunto completo de features (CRM + monitoramento + financeiro + calendário + dashboard + multi-usuário) ou priorizar um subconjunto menor para validar o mercado antes de expandir.

O código-base atual já possui integração com DataJud, DJe TJSP e comunicaapi.pje.jus.br, Inngest para cron jobs e NextAuth com JWT — reduzindo o esforço de infra para o SaaS. O mercado tem 1,3 milhão de advogados, com 73% de adoção de software mas apenas 31% de satisfação, apontando para oportunidade de conquistar usuários insatisfeitos com uma oferta completa e bem integrada.

## Decisão

Lançar o JurisRadar SaaS como plataforma completa: CRM de processos + monitoramento em tempo real + financeiro básico + calendário processual + dashboard analítico + escritório multi-usuário + billing. Todas as features entram no produto v1.0, com faseamento interno de implementação mas sem produto público parcial.

## Alternativas Consideradas

### Alternativa A: Core SaaS (MVP Faseado)

- **Descrição**: Lançar apenas com monitoramento + CRM + financeiro básico + billing. Calendário e dashboard avançado entram na Fase 2.
- **Prós**: Menor risco técnico, time-to-market de 3–4 meses, aproveita 70% das integrações existentes, valida PMF antes de investir em features maiores.
- **Contras**: Produto incompleto pode não converter contra Astrea (que já tem calendário e dashboard). Advogados precisam de todas as features para abandonar o software atual.
- **Por que rejeitada**: O mercado está insatisfeito com ferramentas existentes justamente pela incompletude. Um produto parcial perpetuaria o problema em vez de resolvê-lo.

### Alternativa C: Nicho Vertical

- **Descrição**: Construir para um segmento específico (ex.: trabalhista ou previdenciário) com automação de workflow vertical, templates e financeiro ajustado para o nicho.
- **Prós**: Maior willingness to pay, menos concorrência direta, produto mais focado.
- **Contras**: TAM inicial menor, contradiz o posicionamento generalista já existente no JurisRadar, exige pesquisa de nicho adicional antes de construir.
- **Por que rejeitada**: O JurisRadar já atende múltiplos tribunais e áreas; um pivot para nicho perderia o investimento existente em integrações amplas.

## Consequências

### Positivas

- Produto completo desde o lançamento reduz fricção de adoção — advogado não precisa de outra ferramenta em paralelo.
- Posicionamento premium justificado pelo conjunto de features, diferenciando do Juridiq (R$80, muito limitado).
- Uma única proposta de valor clara: "único lugar onde o advogado precisa estar".

### Negativas

- Prazo estimado de 8–12 meses até lançamento público — maior risco de mercado mudar durante o desenvolvimento.
- Custo de desenvolvimento maior; sem receita até o lançamento completo.
- Mais complexidade técnica a gerenciar simultaneamente (multi-tenancy + billing + calendar + financial).

### Riscos

- **Risco de escopo crescente**: com todas as features no plano, é fácil adicionar "mais uma coisa". Mitigação: PRD congela o escopo v1.0 e qualquer adição exige ADR.
- **Risco de atraso**: 8–12 meses é estimativa otimista. Mitigação: faseamento interno de desenvolvimento com milestones claros e produto em staging com beta testers a partir do mês 6.

## Notas de Implementação

O faseamento interno recomendado é: (1) auth + multi-tenant + billing → (2) import OAB/CPF + CRM + monitoring → (3) notifications → (4) financial → (5) calendar + dashboard. Beta fechado começa após milestone 3.
