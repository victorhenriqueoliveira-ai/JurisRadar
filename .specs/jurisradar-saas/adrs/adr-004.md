# ADR-004: Design System — Tokens Compartilhados entre shadcn/ui e uiverse.io

## Status

Aceito

## Data

2026-08-19

## Contexto

O JurisRadar SaaS quer uma interface moderna e diferenciada visualmente. O projeto atual usa shadcn/ui (componentes de formulário, tabelas, dialogs) + Tailwind CSS. O usuário quer incorporar componentes do uiverse.io (botões animados, cards glassmorphism, loaders, efeitos visuais) para criar uma identidade visual premium que os concorrentes (Astrea, ADVBox) não têm. O desafio é manter consistência visual entre os dois sistemas sem duplicar variáveis CSS ou criar conflitos de estilo.

## Decisão

Criar uma camada de design tokens centralizada em `src/styles/tokens.css` usando CSS custom properties. O shadcn/ui já usa tokens via `--background`, `--foreground`, `--primary` etc. Os componentes do uiverse.io, ao serem copiados, terão seus valores hardcoded substituídos pelas mesmas CSS variables do shadcn/ui. A paleta jurídica do JurisRadar (azul-marinho, dourado) será definida uma vez nos tokens e propagada para ambos os sistemas.

## Alternativas Consideradas

### Alternativa A: Copy-paste seletivo sem tokens

- **Descrição**: Copiar componentes do uiverse.io sem integração sistemática, apenas ajustando cores manualmente.
- **Prós**: Rápido de implementar; sem overhead de design system.
- **Contras**: Inconsistência visual com o passar do tempo; impossível mudar a paleta de cor globalmente; dark mode precisa ser implementado duas vezes.
- **Por que rejeitada**: Gera dívida técnica visual que aumenta a cada novo componente adicionado.

### Alternativa B: Substituir shadcn/ui pelo uiverse.io

- **Descrição**: Usar uiverse.io como design system primário, remover shadcn/ui.
- **Prós**: Visual totalmente diferenciado, sem "cara de shadcn/ui".
- **Contras**: uiverse.io é uma galeria de componentes individuais, não um design system coeso. Falta acessibilidade (ARIA), composabilidade e primitivos de formulário que o shadcn/ui (baseado em Radix UI) oferece.
- **Por que rejeitada**: Regressão de acessibilidade e DX inaceitável para um produto SaaS profissional.

## Consequências

### Positivas

- Dark mode implementado uma única vez nos tokens — propaga para shadcn/ui e componentes uiverse.io automaticamente.
- Mudança de paleta de cor = alterar tokens, não caçar `#1a2b3c` espalhado pelo código.
- Componentes uiverse.io mantêm suas animações e efeitos visuais premium enquanto usam as cores do sistema.

### Negativas

- Cada componente copiado do uiverse.io precisa de uma passagem para substituir valores hardcoded por tokens — overhead de ~15 min por componente.
- Equipe precisa conhecer o mapeamento de tokens para não introduzir cores hardcoded.

### Riscos

- **Conflito de especificidade CSS**: componentes uiverse.io frequentemente usam seletores de classe de alta especificidade que podem sobrepor estilos Tailwind. Mitigação: usar `@layer components` no Tailwind para encapsular estilos uiverse.io.

## Notas de Implementação

Tokens prioritários a definir em `src/styles/tokens.css`:
- `--jr-primary`: azul-marinho jurídico (tom a definir no design)
- `--jr-accent`: dourado/âmbar para CTAs e destaques
- `--jr-success`, `--jr-warning`, `--jr-danger`: semáforo de urgência processual
- `--jr-glass-bg`, `--jr-glass-border`: para cards glassmorphism do uiverse.io
- `--jr-gradient-start`, `--jr-gradient-end`: gradientes do dashboard

Componentes uiverse.io prioritários para o JurisRadar:
- Botão com efeito ripple/glow (CTA principal)
- Card glassmorphism (cards de métricas do dashboard)
- Loader animado (tela de importação de processos no onboarding)
- Badge com pulso animado (notificações urgentes)
- Empty state ilustrado (seções sem dados)
- Toggle switch estilizado (preferências de notificação)
