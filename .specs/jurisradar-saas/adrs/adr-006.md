# ADR-006: Resend como Provedor de E-mail Transacional

## Status

Aceito

## Data

2026-08-19

## Contexto

O JurisRadar SaaS precisa enviar e-mails transacionais: notificações de intimações, alertas de prazo, convites para membros do escritório, e-mails de onboarding, resumos diários e alertas de billing. O projeto não tem nenhuma integração de e-mail atualmente.

## Decisão

Usar Resend como provedor de e-mail transacional. Templates de e-mail construídos com React Email (`@react-email/components`) para reutilizar o mesmo ecossistema React do projeto Next.js.

## Alternativas Consideradas

### Alternativa B: SendGrid

- **Descrição**: Provedor maduro com alta deliverability, templates drag-and-drop e analytics detalhados.
- **Prós**: Alta deliverability; suporte robusto; analytics granulares.
- **Contras**: SDK mais verboso; templates em JSON/drag-and-drop, não em código; DX inferior para projetos Next.js.
- **Por que rejeitada**: DX significativamente pior que Resend para projetos TypeScript/React.

### Alternativa C: Nodemailer + Amazon SES

- **Descrição**: SMTP via Amazon SES com Nodemailer como cliente.
- **Prós**: Custo muito baixo ($0,10 por 1.000 e-mails); controle total.
- **Contras**: Setup de SES requer saída do sandbox da AWS (aprovação manual); sem portal de templates; mais configuração de infraestrutura.
- **Por que rejeitada**: Overhead de infra e aprovação AWS injustificado quando o Resend resolve com zero config.

## Consequências

### Positivas

- Templates em React/TSX reutilizam componentes e tipos TypeScript do projeto.
- Preview local de templates com `react-email dev` sem envio real.
- Plano gratuito (3.000 e-mails/mês) cobre o beta fechado sem custo.
- SDK: `import { Resend } from 'resend'` — integração em < 10 linhas.

### Negativas

- Resend é mais novo que SendGrid; menor histórico de uptime em escala.
- Análises de deliverability menos granulares que SendGrid para diagnóstico de problemas de entrega.

### Riscos

- **Rate limits**: Plano gratuito permite 100 e-mails/dia. Com 500 advogados e notificações frequentes, plano pago (Starter $20/mês) é necessário em produção. Mitigação: configurar plano pago antes do beta.

## Notas de Implementação

- Criar `src/lib/email/` com: `resend.ts` (cliente singleton), `templates/` (componentes React Email), `send-notification.ts` (helper tipado).
- Templates prioritários: `NotificacaoIntimacao.tsx`, `AlertaPrazo.tsx`, `ConviteMembro.tsx`, `WelcomeOnboarding.tsx`, `ResumoDiario.tsx`, `FalhaBilling.tsx`.
- Enfileirar envios via Inngest (`notificacao-dispatcher`) em vez de chamar Resend diretamente nas API Routes — evita timeout e garante retry.
