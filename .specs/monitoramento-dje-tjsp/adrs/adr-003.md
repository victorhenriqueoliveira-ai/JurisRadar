ADR-003: Biblioteca de Extração de PDF — pdf-parse

## Status

Aceito

## Data

2026-08-07

## Contexto

Os cadernos do DJE/TJSP são disponibilizados em formato PDF. Para indexar o conteúdo, é necessário extrair o texto bruto do PDF no ambiente de execução do projeto: Next.js (Node.js) hospedado na Vercel. O ambiente Vercel não permite binários nativos nem processos filhos — a biblioteca deve funcionar inteiramente em JavaScript/Node.js puro.

O DJE/TJSP é um PDF textual (não imagem escaneada), o que significa que a extração de texto é direta, sem necessidade de OCR.

## Decisão

Usar `pdf-parse` como biblioteca de extração de texto. A chamada central é:

```typescript
import pdfParse from 'pdf-parse';

export async function extractTextFromPdf(buffer: Buffer): Promise<string> {
  const { text } = await pdfParse(buffer);
  return text;
}
```

## Alternativas Consideradas

### Alternativa: unpdf

- **Descrição**: fork moderno do pdfjs-dist, otimizado para edge runtime e Vercel; API baseada em Web Streams
- **Prós**: mais ativo em manutenção que pdf-parse; suporte a edge runtime; API moderna
- **Contras**: mais pesado; overhead de configuração; comunidade menor
- **Por que rejeitada**: a feature roda em Inngest (Node.js, não edge runtime) — o suporte a edge é irrelevante; pdf-parse entrega o resultado com API mais simples para o caso de uso

### Alternativa: pdfjs-dist (Mozilla)

- **Descrição**: biblioteca oficial do Mozilla para rendering e parsing de PDF; suporte a PDFs complexos com layouts tabulares
- **Prós**: mais robusta para PDFs com layouts complexos; suporte oficial e amplo
- **Contras**: ~5MB de tamanho; requer configuração de worker em Node.js; API assíncrona por página mais verbosa
- **Por que rejeitada**: o DJE é PDF textual simples — a complexidade adicional não se justifica; tamanho de bundle maior penaliza cold starts na Vercel

## Consequências

### Positivas

- API mínima: uma chamada, retorna texto como string
- Zero binários nativos: compatível com Vercel serverless sem configuração adicional
- Bundle pequeno (~200KB)

### Negativas

- `pdf-parse` tem histórico de manutenção irregular — se o TJSP usar features avançadas de PDF em versões futuras, pode falhar
- Sem controle de extração por página — texto é concatenado; precisa de lógica própria para segmentar publicações dentro do texto extraído

### Riscos

- O TJSP pode mudar o gerador de PDF do caderno; se o novo PDF tiver texto embutido em imagem (scanned), pdf-parse retornará texto vazio — mitigar com validação de sanidade (contagem de processos extraídos abaixo de threshold)

## Notas de Implementação

- Adicionar `pdf-parse` e `@types/pdf-parse` nas dependências de produção
- O buffer do PDF deve ser obtido via `fetch` com `response.arrayBuffer()` e convertido para `Buffer.from(arrayBuffer)`
- Testar com um caderno real do TJSP antes de mergear a implementação do parser
