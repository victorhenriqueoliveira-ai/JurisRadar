ADR-004: Estratégia de Resultados de Busca DJE — Requery ao Vivo sem Snapshot

## Status

Aceito

## Data

2026-08-07

## Contexto

O JurisRadar DataJud persiste resultados de busca em tabela `search_results` (snapshot por execução) porque os dados do DataJud são efêmeros — uma consulta repetida ao DataJud pode retornar resultados diferentes conforme a indexação evolui, e a Inngest job é assíncrona.

Para o DJE, o modelo é diferente: as publicações estão indexadas localmente no banco (`dje_publications`) e a busca é síncrona. A pergunta é se o resultado de uma busca DJE deve ser salvo como snapshot ou rederivado ao vivo a cada acesso.

## Decisão

Não persistir snapshot de resultados de busca DJE. A tabela `dje_searches` armazena apenas os parâmetros da busca (termo + período + total de resultados na execução). Toda visualização de resultado, paginação e exportação CSV re-executa a query no índice ao vivo.

## Alternativas Consideradas

### Alternativa: Snapshot de Resultados (como DataJud)

- **Descrição**: criar `dje_search_results` análoga a `search_results`, persistindo cada publicação encontrada por busca
- **Prós**: resultado histórico exato — o advogado vê exatamente o que foi retornado naquela data; exportação CSV opera sobre dados já materializ ados
- **Contras**: duplicação de dados (as publicações já estão em `dje_publications`); crescimento quadrático do banco (N buscas × M resultados); complexidade adicional sem benefício real, pois o índice DJE é nosso e não muda retroativamente — uma publicação de 01/08/2026 continuará sendo a mesma se o advogado rever a busca em setembro

- **Por que rejeitada**: o dado-fonte está no banco e é imutável por data — re-executar a query retorna exatamente o mesmo resultado para o mesmo período; snapshot é redundante e aumenta armazenamento desnecessariamente

## Consequências

### Positivas

- Schema mais simples: apenas `dje_searches` (sem `dje_search_results`)
- Zero duplicação de dados
- CSV export re-executa query — sem limite de linhas por execução prévia, sempre retorna o conjunto completo atual
- "Reexecutar" é transparente: nova entrada em `dje_searches` com os mesmos filtros

### Negativas

- Se uma publicação for corrigida ou removida do índice (ex.: reprocessamento de edição com erro), o resultado histórico muda retroativamente — aceitável para o MVP
- Export CSV em busca com muitos resultados faz full query no momento da exportação — mitigar com timeout de export ou limite de linhas por export

### Riscos

- Reprocessamento de uma edição DJE (ex.: correção de parser) altera resultados retroativamente — documentar como comportamento esperado, não bug

## Notas de Implementação

- `dje_searches.total_results` é registrado no momento da execução e reflete o histórico do usuário no dashboard — não precisa ser rederivado
- O endpoint de exportação CSV deve rederiviar a query usando os campos `term`, `date_from`, `date_to` da `dje_searches` sem limite de pagination
